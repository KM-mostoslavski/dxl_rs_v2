# Typed limit setters: implementation plan

**Goal:** every EEPROM limit that most actuators share is read and written through typed calls on `ActuatorRef`, in SI units, with checks of their own, so a caller never needs `write_raw` for it. `raw-registers` stays for registers specific to one series (maintainer, 2026-11-09).

**Why now:** kmr widens an AX-12A's voltage limits for a run and restores them at the end (NFR-11, decided 2026-11-09: the caller saves and restores). Today that needs `write_raw` with no torque, range or order check, and a hand-made V → raw conversion (`examples/ax12_sine`).

**Spec:** maintainer's request of 2026-11-09 ("we need proper setters", "also implement the other limit setters"). It overrides FR-9 "Out of scope: writing EEPROM registers … still `write_raw`" and answers part of § 8 "Typed EEPROM writes" (`specs/ideas/eeprom-writes.md`); the SRS text is T096, the architect's. NFR-11 restore stays the caller's: no save/restore helper in the crate.

## Decisions (taken on the maintainer's order, recorded for T096)

- **D1. Scope: the limits most models share.**

  | Field | Registers (table names) | Value | Tables with it |
  |---|---|---|---|
  | `MinVoltageLimit`, `MaxVoltageLimit` | Min / Max Voltage Limit | `Voltage` (V) | 76 of 76 |
  | `TemperatureLimit` | Temperature Limit | `Temperature` (°C) | 64 |
  | `MinPositionLimit`, `MaxPositionLimit` | Min / Max Position Limit (P2), CW / CCW Angle Limit (P1) | `Position` (rad) | 76 |
  | `VelocityLimit` | Velocity Limit | `Velocity` (rad/s) | 66 |
  | `CurrentLimit` | Current Limit | `Current` (A) | 60 |
  | `PwmLimit` | PWM Limit | `Pwm` (new, a ratio 0..=1) | 66 |
  | `MaxTorque` | Max Torque (P1 EEPROM) | `Load` (a ratio of the maximum torque) | 10 |

  Left raw, specific to one series: the Y-only Motor and Inverter Temperature Limit, Position Limit Threshold, In-Position and Following Error Threshold (12 tables). Acceleration Limit (MX(2.0), PRO, PRO+, Y and RH-P12-RN: 28 of 76 tables) is typed by D10. Not limits, left for later: Moving Threshold, Torque Limit (P1 RAM), ID, baud rate, Return Delay Time, Status Return Level.
- **D2. Writes are unicast only, through a trait of their own.** New sealed `pub trait LimitField: Field` (`type Value`), implemented by the D1 fields and by `Raw<F>` (`i32`). The D1 fields implement `ReadField` (so `read`, `read_field`, `sync_read`, `bulk_read` save them, for NFR-11) but not `WriteField`: `write`, `sync_write` and `bulk_write` refuse them at compile time (Principle II). A sync or bulk write gets no reply, so the bus could neither confirm the write nor keep its cache true (D4).
- **D3. API on `ActuatorRef`** (so on `Bus` and `DynBus` handles alike):
  - `write_limit<F: LimitField>(&mut self, field: F, value: F::Value) -> Result<(), Error>`;
  - pair setters `set_voltage_limits(min: Voltage, max: Voltage)` and `set_position_limits(min: Position, max: Position)`;
  - setters `set_temperature_limit(Temperature)`, `set_velocity_limit(Velocity)`, `set_current_limit(Current)`, `set_pwm_limit(Pwm)`, `set_max_torque(Load)`;
  - getters, one unicast read each, never cached: `voltage_limits() -> (Voltage, Voltage)`, `temperature_limit()`, `velocity_limit()`, `current_limit()`, `pwm_limit()`, `max_torque()`. Position limits read through `Actuator::position_limits` (the cache, kept true by D4) or `read(MinPositionLimit)`; no inherent `position_limits` so the trait method is not shadowed.
- **D4. Checks before a byte is sent, in this order:** the model has the register (`Unsupported`); the torque state the bus holds is not `On` (new `ValidationError::ActuatorIsOn { id, register }`, hint "disable torque before writing EEPROM"): the bus's rule on every model, which X-series, MX(2.0) and XL-320 firmware also enforce while the AX, RX and MX Protocol 1 pages document no such lock; `Off` and `Faulted` both pass, so a faulted actuator held by Setup (D-01) can be fixed (that this trusts a state the hardware may not share is deferred, `docs/deferred.md` 2026-11-09); the value converts (`NoUnit`, `NotFinite`, `DoesNotFit`); it lies in the e-Manual range (`OutOfLimits`): the `unit_info` range, or for position limits the e-Manual range of the limit row (row or `unit_info` range, which must contain the `type_info` position range: a Y limit may span the whole `i32`); a register whose table records no range gets only the size check; pairs stay ordered (`InvertedLimits`): a pair setter checks its two values, a single position-limit write checks against the other cached limit, a single voltage-limit write cannot (the other limit is not cached and a read would be hidden, FR-9.6) and says so in its docs.
- **D5. The cache follows the write.** A write acknowledged without error updates what Setup cached: position limits (`Limits`), on Protocol 1 also the limit mode (`LimitMode::from_angle_limits`: CW = CCW = 0 is wheel mode, on MX CW = CCW = 4095 multi-turn), and the goal bound when the recorded mode uses Velocity or Current Limit. A write that fails after bytes went out leaves that cache unknown (`goal_bound_raw` then `None`): every goal that depends on it is refused (`LimitsUnknown`), and on Protocol 1 Moving Speed too while the wheel/joint mode is unknown. A write acknowledged without error that fully determines a cached item makes it known again, instead of leaving it unknown until the next Setup (plan owner, 2026-11-09): a pair write (`set_position_limits`, or both limits through one write) restores `Limits` and, on Protocol 1, the limit mode from those two values; a Velocity/Current Limit write restores the goal bound. A single position-limit write whose other limit is unknown stays refused. Voltage, temperature, PWM and Max Torque are not cached.
- **D6. Units from the tables only (FR-9.2, Principle IV).** A model whose table has no `unit_info` for the register refuses the typed form with `NoUnit`; its raw form (`write_limit(Raw(F), raw)`) still works, with the torque check and the size check. A typed position limit needs no unit (it converts through `type_info`) but the e-Manual range of its row, which only a verified table records: without it the typed form is refused with `NoUnit` too. T097 adds the missing `unit_info` rows to the six verified tables from their e-Manual pages. The other 70 tables get typed limits when they are verified, as every FR-9 register.
- **D7. `Pwm`** is a new newtype beside `Load` (`units`), same shape: a ratio, `from_ratio`, `ratio`, raw conversion through the model's scale (`unit: "%"`).
- **D8. Torque confirmed off** (plan owner, 2026-11-09; closes the first `docs/deferred.md` row of 2026-11-09 and supersedes D4's "`Off` and `Faulted` both pass"). The bus keeps, per actuator, a private "torque confirmed off" mark. Only a Torque Enable = 0 write whose reply shows the instruction ran sets it: no error, or hardware-fault flags only (Protocol 1: Input Voltage, Overheating, Overload; Protocol 2: the alert bit with no error code), so `disable_torque()` confirms a faulted actuator held by Setup even though its reply carries the fault. It is clear after Setup (the hardware's Torque Enable is never read, FR-2.7), and cleared by every `enable_torque` that sent bytes, by a Torque Enable write without such a reply, by `reboot()` (Startup Configuration may turn torque on), by `clear_fault()` where it reboots, and by every raw write that reaches the actuator (`write_raw`, a raw bulk write part, a raw broadcast), which may touch Torque Enable. A limit write passes the torque check only with the mark: torque state `On` gives `ActuatorIsOn` as before, any other state without the mark gives the new `ValidationError::TorqueUnconfirmed { id, register }`, hint "call disable_torque() before writing EEPROM". The bus never writes Torque Enable on its own (Principle III).
- **D9. No switch to wheel mode with a live speed** (plan owner, 2026-11-09; closes the second `docs/deferred.md` row of 2026-11-09). On AX, RX and MX on Protocol 1 a limit write that switches the limit mode to `Wheel` (CW = CCW = 0 from any other mode) is refused with the new `ValidationError::WheelSpeedUnknown { id }`, hint "write Moving Speed 0 before switching to wheel mode" (`set_speed_limit(SpeedLimit::Unlimited)`, or `write(Raw(SpeedLimit), 0)` where the table has no unit), unless the bus knows Moving Speed is 0: a private mark set by an acknowledged unicast write of Moving Speed = 0 (`set_speed_limit(SpeedLimit::Unlimited)`, `write(Raw(SpeedLimit), 0)`), clear after Setup, cleared by any other Moving Speed write on any tier (a sync or bulk write gets no reply, so it clears and never sets), by raw writes and by `reboot()`. Leaving wheel mode is not refused.
- **D10. Acceleration Limit is typed** (maintainer's rule: raw only for one series; it is in 28 tables across MX(2.0), PRO, PRO+, Y and RH-P12-RN). Field `AccelerationLimit`, value the new newtype `units::Acceleration` (rad/s², same shape as `Velocity`), setter `set_acceleration_limit`, getter `acceleration_limit`; the scale and range come from `unit_info` (D6), added from the e-Manual to the verified table that has the register (`mx_64.ron`); not cached.

## Review focus

- No path writes EEPROM while torque is `On`, on any tier.
- The cache can never hold a limit the actuator does not have: after a failed write, goals that depend on it are refused.
- Protocol 1 angle-limit writes switch the limit mode exactly as Setup would have recorded it.
- Every unit and range comes from a table row backed by the e-Manual.
