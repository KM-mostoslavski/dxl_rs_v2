# Contract: generated `models` module

**Feature**: [../spec.md](../spec.md) | **Model**: [../data-model.md](../data-model.md) |
**Cross-module contract**: `specs/ideas/module-interfaces.md` §4

This is what `cargo xtask codegen` writes into `src/models.rs` and `src/models/`. Signatures and
`cfg` rules are the contract. Bodies are shown only where the shape matters to the bus.
`Register`, `Access`, `Area`, `ModelData`, `LimitRegisters`, `Protocols`, `ModeSource`, `Cache`,
`Describe`, `Actuator`, `PositionScale`, `ModelNumber`, `Id`, `SetupError` and `ProtocolVersion`
are owned by core or protocol (contract §2, §5). Generated code only uses them.

## Imports

Each generated file has its own `use` lines, only for what it uses in every family combination
in which it compiles (research R-10). There is no shared import block. Items are named by their
owning module, as in the table "Paths for xtask and bus" in
`specs/004-core/contracts/core-api.md`; no root re-export is used (research R-12).

`src/models.rs` compiles with no family too:

```rust
use crate::actuator::{Actuator, Cache, Describe, ModelData, ModelNumber}; // core-1 (C1: Describe)
use crate::error::SetupError;                                             // core-1
use crate::id::Id;
use crate::protocol::ProtocolVersion;                                     // contract §5 (PR #7, merged)
use crate::register::{Access, Area, Register};                            // core-1
```

`src/models/<module>.rs` compiles only with its family:

```rust
use crate::actuator::{Actuator, Cache, Describe, LimitRegisters, ModeSource, ModelData, Protocols};
use crate::id::Id;
use crate::register::{Access, Area, Register};
use crate::units::PositionScale;
```

`src/models/tests.rs` imports at the top only what the tests compiled in every combination use
(the unknown-number test):

```rust
use super::ActuatorKind;
use crate::actuator::ModelNumber;
use crate::error::SetupError;
use crate::id::Id;
use crate::protocol::ProtocolVersion;
```

A family-gated test imports what else it needs (`crate::actuator::{Cache, Describe, LimitMode}`,
its model type) inside its own body.

## `src/models.rs`

```rust
// @generated by `cargo xtask codegen`. Do not edit: change `control_tables/` and regenerate.
//! Actuator model types, one per control table.

#![allow(
    dead_code,
    unused_variables,
    clippy::approx_constant,
    reason = "every register is generated but only some are used; with no family enabled some \
              parameters are unused; type_info angles are table data, not uses of π"
)]

// use lines: see "Imports"

#[cfg(feature = "x-series")]
mod xm430_w350;
#[cfg(feature = "x-series")]
pub use xm430_w350::Xm430W350;
// ... one pair per table, ordered by model number, then by from_fw

#[cfg(test)]
mod tests;

/// Builds one register row. Private to `models`; model files call `super::reg`.
const fn reg(addr: u16, size: u8, access: Access, area: Area) -> Register;

/// Model Number location, the same in every table (codegen checks it). Read on P1 Setup.
pub(crate) const MODEL_NUMBER: Register = reg(0, 2, Access::R, Area::Eeprom);

/// Any supported actuator, one variant per model type.
///
/// Match on it to reach a model's own features; use the [`Actuator`] trait for what every
/// model has in common.
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub enum ActuatorKind {
    /// XM430-W350 (model number 1020). Protocol 1 and 2, all firmware.
    #[cfg(feature = "x-series")]
    Xm430W350(Xm430W350),
    // ... one variant per table file
}

impl ActuatorKind {
    /// The variant for `model_number` on `protocol`, using the table whose `from_fw` is the
    /// highest not above `firmware`.
    ///
    /// Fails with [`SetupError::UnsupportedModel`]: `feature` is the family to enable when the
    /// model has tables on this protocol but its family is off, and `None` otherwise.
    pub(crate) fn new(
        protocol: ProtocolVersion,
        model_number: ModelNumber,
        firmware: u8,
        id: Id,
    ) -> Result<Self, SetupError>;

    /// `Some` when this model's table depends on firmware on this protocol: the Firmware
    /// Version register to read before calling [`ActuatorKind::new`]. `None` otherwise,
    /// including when the model's family is off.
    pub(crate) fn firmware_register(
        protocol: ProtocolVersion,
        model_number: ModelNumber,
    ) -> Option<Register>;
}

impl Describe for ActuatorKind {
    fn data(&self) -> &'static ModelData;      // match *self { Self::X(ref m) => m.data(), .. }
    fn cache(&self) -> &Cache;                 // match *self { Self::X(ref m) => m.cache(), .. }
    fn cache_mut(&mut self) -> &mut Cache;     // match *self { Self::X(ref mut m) => .., .. }
}

impl Actuator for ActuatorKind {
    fn id(&self) -> Id;                        // emitted while core-1's trait requires them;
    fn model_number(&self) -> u16;             // a regeneration after core-2 may drop them
    fn name(&self) -> &'static str;
}
```

### Lookup semantics

The body of `new` is a single `match (protocol, model_number.get())`:

```rust
#[cfg(feature = "x-series")]
(ProtocolVersion::P2, 1190) if firmware < 53 => Ok(Self::Xl330M077Fw52(Xl330M077Fw52::new(id))),
#[cfg(feature = "x-series")]
(ProtocolVersion::P2, 1190) => Ok(Self::Xl330M077(Xl330M077::new(id))),
#[cfg(not(feature = "x-series"))]
(ProtocolVersion::P2, 1190) => Err(/* UnsupportedModel { feature: Some("x-series") } */),
// ...
_ => Err(/* UnsupportedModel { feature: None } */),
```

| Model number on this protocol | Family on | Family off |
|---|---|---|
| Has tables | `Ok(variant)` for the highest `from_fw ≤ firmware` | `UnsupportedModel { feature: Some(family) }` |
| Known, but no tables on this protocol | `UnsupportedModel { feature: None }` | same |
| Unknown | `UnsupportedModel { feature: None }` | same |

`UnsupportedModel` always carries `id`, `model_number` (as `u16`) and `protocol`. No arm can
panic, and none does arithmetic.

`firmware_register` body:

```rust
#[cfg(feature = "x-series")]
(ProtocolVersion::P2, 1190) => Some(Xl330M077Fw52::FIRMWARE_VERSION),
// ... one arm per (protocol, model number) with more than one table
_ => None,
```

## `src/models/<module>.rs` (one per mapped table file)

```rust
// @generated by `cargo xtask codegen`. Do not edit: change `control_tables/` and regenerate.
// Source: control_tables/xm430_w350.ron

// use lines: see "Imports"

/// XM430-W350 (model number 1020).
///
/// Protocol 1, all firmware. Protocol 2, all firmware.
///
/// Source table: `control_tables/xm430_w350.ron`.
/// Unverified: not yet checked against the ROBOTIS e-Manual.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Xm430W350 {
    cache: Cache,
}

impl Xm430W350 {
    pub(crate) const fn new(id: Id) -> Self;

    pub(crate) const DATA: ModelData = ModelData {
        name: "XM430-W350",
        model_number: 1020,
        protocols: Protocols { p1: true, p2: true },
        torque_enable: Self::TORQUE_ENABLE,
        goal_position: Self::GOAL_POSITION,
        present_position: Self::PRESENT_POSITION,
        limits: LimitRegisters::MinMax { min: Self::MIN_POSITION_LIMIT, max: Self::MAX_POSITION_LIMIT },
        hardware_error: Some(Self::HARDWARE_ERROR_STATUS),
        mode: ModeSource::OperatingMode(Self::OPERATING_MODE),
        scale: PositionScale::new(2048, 0, 4095, -3.1415927, 3.1400588),
    };

    pub(crate) const MODEL_NUMBER: Register = super::reg(0, 2, Access::R, Area::Eeprom);
    pub(crate) const OPERATING_MODE: Register = super::reg(11, 1, Access::RW, Area::Eeprom);
    pub(crate) const TORQUE_ENABLE: Register = super::reg(64, 1, Access::RW, Area::Ram);
    // ... one constant per row, in table order
}

impl Describe for Xm430W350 {
    fn data(&self) -> &'static ModelData;      // &Self::DATA
    fn cache(&self) -> &Cache;                 // &self.cache
    fn cache_mut(&mut self) -> &mut Cache;     // &mut self.cache
}

impl Actuator for Xm430W350 {
    fn id(&self) -> Id;                        // self.cache.id()
    fn model_number(&self) -> u16;             // 1020
    fn name(&self) -> &'static str;            // "XM430-W350"
}
```

Scale literals: the four integers are the table's `type_info` values. Each radian value is the
`{:?}` text of the table value parsed as `f32` (research R-6), not the table text. Tests build the
expected text the same way, with `format!("{:?}", v)` from the table or fixture value; no test
hard-codes a radian literal. The line above shows T1's corrected values (`-3.1415927`,
`3.1400587` in the table); before T1 the tables give ±π. For AX and XL-320, T1's `-2.6205530` and
`2.6154347` render as `-2.620553` and `2.6154346`.

Variations:

- CW/CCW tables (AX, XL-320, MX on P1): `limits: LimitRegisters::CwCcw { cw: Self::CW_ANGLE_LIMIT, ccw: Self::CCW_ANGLE_LIMIT }`.
- Mode source (contract §2.4b, research R-17): an `Operating Mode` row gives
  `mode: ModeSource::OperatingMode(Self::OPERATING_MODE)` (X, MX(2.0), PRO, PRO+, Y); XL-320 gives
  `mode: ModeSource::ControlMode(Self::CONTROL_MODE)`; a table with no mode register (AX, MX on P1)
  gives `mode: ModeSource::AngleLimits`.
- No `Hardware Error Status` row (AX; Y-series until verified): `hardware_error: None`.
- A verified table: `Verified against <url> on <YYYY-MM-DD>.` replaces the Unverified line.
- `also` names: `(model number 12, also sold as AX-12+)`.
- A firmware variant: `Protocol 2, firmware up to v52.` / `Protocol 2, firmware v53 and later.`

## Visibility summary

| Public (documented) | Crate-internal |
|---|---|
| `models` module, every model type (as a `match` target), `ActuatorKind` and its variants | `new`, `DATA`, every register constant, the `cache` field, `MODEL_NUMBER`, `ActuatorKind::new`, `firmware_register`; `reg` is private to `models` |

No generated item is `dyn`, allocates, or contains `unwrap`, `expect`, `panic!`, indexing or
arithmetic outside `const` initialisers.

## `src/models/tests.rs` (`cfg(test)`)

The checks it makes for each (protocol, model number) and each model type are listed in
[research R-11](../research.md#r-11-tests-xtask-fixtures-real-tables-and-generated-crate-tests)
layer 3. Family-on checks sit under `cfg(feature = family)`, and family-off checks under
`cfg(not(feature = family))`. The file compiles with no warnings in every family combination.
It names registers and model data only by constant (`<Type>::FIRMWARE_VERSION`, `<Type>::DATA`,
`MODEL_NUMBER`), never by literal address or size, so a one-row table change still changes one
generated file (SC-007).
