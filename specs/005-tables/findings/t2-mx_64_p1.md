## Model data

- Model number: the page's Model Number row, Initial Value **310** (research R-11: 310). Map
  name "MX-64" (T062), as research R-11 and the contract example; the page title is
  "MX-64T/R/AT/AR".
- `protocols: [P1]`: no Protocol Type register on the page; "Please refer to DYNAMIXEL Protocol 1.0
  for more details about Instruction Packets"; "NOTE: MX(2.0) is a special firmware … supporting
  the DYNAMIXEL Protocol 2.0"; "WARNING : For MX-64(2.0) Protocol, please refer to the MX-64(2.0)
  Control Table as they are different."
- Mode source (FR-020, US5 AS6): **no `Operating Mode` register** on the page (the Specifications
  row "Operating Modes: Wheel Mode (Endless Turn), Joint Mode (0 ~ 360 [°]), Multi-turn Mode" is a
  feature line, not a register). CW/CCW Angle Limit (6, 8) present: "Wheel Mode: both CW and CCW
  are 0; Joint Mode: neither CW or CCW are 0; Multi-turn Mode: both CW and CCW are 4095". No
  `operating_modes`. Matches module-interfaces §2.4b (`AngleLimits`, 4095/4095 → Unbounded).
- `type_info`: `2048 / 0 / 4095`, `min_radian: -3.1415927`, `max_radian: 3.1400587`. Page: Goal
  Position "0 to 4,095 (0xFFF) is available. The unit is 0.088 [°]"; specification "Resolution
  4096 [pulse/rev]", "Position Sensor … (12Bit, 360 [°])"; the Goal Position figure
  (`/assets/images/dxl/mx/mx_position.png`) labels "180° [Goal Position = 2048(0x800)]". Zero 2048,
  slope 2π/4096 (research R-8: −2048 ticks → −π, +2047 ticks → π·2047/2048).
- `unit_info` (only values the page gives):
  - `Goal Position` / `Present Position` 0.088 deg unsigned ("The unit is 0.088 [°]", 0 ~ 4095).
  - `Moving Speed` 0.114 rpm signed ("the unit is about 0.114rpm"; wheel mode 0 ~ 2047 with "the
    10th bit becomes the direction bit").
  - `Present Speed` 0.11 rpm signed ("The value unit is about 0.11rpm", direction bit). The page
    gives 0.114 for Moving Speed and 0.11 for Present Speed; each is copied as given.
  - `Goal Torque` 4.5 mA signed ("the unit is 4.5mA", direction bit 10).
  - `Goal Acceleration` 8.583 deg/s^2 unsigned ("the unit is approximately 8.583 [° / sec2]").
  - Not written: `Current` (`I = 4.5mA * (CURRENT – 2048)`: an offset the `unit_info` shape cannot
    carry), voltage/temperature (no `unit_info` shape used for them in the MX tables).
  - Reviewer note: "signed" for a direction-bit value (sign and magnitude), as in `rx_28`/AX-12A.
- `instructions` (Protocol 1.0 page, "Instruction" table and per-instruction "Supported products"):
  - P1: `Ping, Read, Write, RegWrite, Action, FactoryReset, SyncWrite, BulkRead`. Bulk Read:

## Page notes (for the architect)

1. **Torque Ctrl Mode Enable (70), RAM**: "1: Turn on the torque mode. Cannot control the position
   or moving speed … DYNAMIXEL does not affected by the Goal Position(30)". So with CW/CCW in
   joint range the actuator can still ignore Goal Position. The mode source (`AngleLimits`,
   §2.4b) does not see this register; a goal write then passes the bounded check and is ignored
   by the firmware. Not a mode register by name (not "Operating Mode"), so the task goes on;
   raised as a question. Same register on MX-28/MX-106 P1 pages if they have it (T076/T077).
2. **Multi Turn Offset (20) / Resolution Divider (22)** NOTE: "can be applied in Munti-turn Mode
   only (The condition that both CW and CCW are 0 …)" contradicts the CW/CCW table on the same
   page ("Multi-turn Mode: Both CW and CCW are 4095"; "Wheel Mode: both CW and CCW are 0"). The
   table wins (and matches §2.4b); recorded.
3. **Realtime Tick (50)**: "This feature is available from Firmware v40." A per-row firmware
   condition; the table format has none, so the row is kept (the page lists it) and the condition
   is recorded here.
4. Multi-turn position range −28,672 ~ 28,672 (two's complement) is outside `type_info`'s
   0..=4095; `type_info` is the joint-mode scale, as for every table. In multi-turn mode §2.4b
   gives `Unbounded` (register size check only).
